### `aiohttp`

* ASGITransport rejected it: TypeError: Application.__call__() takes 1 positional argument but 4 were given

* Rationale: aiohttp.web.Application exposes no ASGI callable: its __call__ is a gunicorn-compatibility stub that takes no arguments and returns self, and the distribution ships no ASGI adapter. The only PyPI shims (aiohttp-asgi, aiohttp-asgi-connector) adapt in the opposite direction — they host an ASGI app on aiohttp's server — so they cannot put an aiohttp app behind ASGITransport. Hand-writing the bridge would measure the bridge, not aiohttp.

### `robyn`

* ASGITransport rejected it: TypeError: 'Robyn' object is not callable

* Rationale: Robyn's Python object configures a compiled Rust server that owns its own socket: the object exposes start()/serve(), defines no __call__, and the package ships no ASGI module (its submodules are router, ws, responses, ... but nothing ASGI). There is no in-process request path to drive, so no comparable number can be produced without measuring Robyn's own server against a socket, which is a different benchmark.
